# Framework Hub — Working Agreement

This repository is the **framework hub** for a weekly AWS Solutions Architecture training program. It holds methodology, prompts, and templates. **No AWS project work happens here** — every weekly project lives in its own repo, scaffolded from here by `/kickoff`.

## What happens in this repo

Only two things:

- **`/kickoff <name>`** — create and scaffold the next project repo, register it in `projects-log.md`
- **`/log-project`** — record a finished project's results back into `projects-log.md`

Plus methodology edits: changes to `setup.md`, `prompts/`, or `templates/` arising from a project retrospective (Stage 8, question 3), each as a standalone commit.

## Boundary reminder

If a session here drifts into doing project work — generating requirements, selecting a domain, making architecture decisions — that is out of place. `/kickoff` explicitly stops short of Stage 1; requirements are generated by `/new-project` inside the project repo, where `CLAUDE.md` carries the full boundary list.

The authoritative boundary list is [templates/CLAUDE-md-template.md](templates/CLAUDE-md-template.md). It is not restated here or in `setup.md` — a rule kept in two places drifts into two different rules.

## Anti-drift rule

`setup.md` describes the methodology and **links** to prompts and templates. It does not contain copies of them. If you find yourself pasting a prompt body or a template body into `setup.md`, stop — that duplication is what caused the last drift, including the silent loss of a prompt-05 boundary line that took a full evaluation campaign to prove out.
